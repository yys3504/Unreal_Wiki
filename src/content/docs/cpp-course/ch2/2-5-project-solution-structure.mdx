언리얼 프로젝트를 처음 열었을 때 보게 되는 **프로젝트 폴더**와 **Visual Studio 솔루션 구조**를 함께
정리합니다. 어디에 에셋과 코드가 모여 있는지, 무엇을 먼저 보면 되는지 빠르게 익히는 것이 목표입니다.

## 프로젝트 폴더 구조

<Figure src="/images/ch2/5/1-project-folder-structure.png" alt="언리얼 프로젝트 폴더 구조 이미지" caption="언리얼 프로젝트 루트 폴더" />

프로젝트 루트에는 개발 결과물과 빌드 산출물이 함께 있습니다. 처음부터 모든 폴더를 외울 필요는
없고, 자주 다루는 핵심 폴더 위주로 이해하면 충분합니다.

<CardGrid>
  <Card title="자주 보는 폴더">

  - ⭐ **Content**: 에셋(머티리얼·메시·맵 등) 저장 위치
  - ⭐ **Source**: C++ 클래스(.h/.cpp)와 모듈 코드
  - **Config**: 프로젝트 설정(.ini) 파일
  - **Plugins**: 플러그인 추가/관리 폴더

  </Card>
  <Card title="자동 생성 / 산출 폴더">

  - **Binaries**: 빌드된 실행/모듈 파일
  - **Intermediate**: 빌드 중간 산출물
  - **Saved**: 로그·자동저장·임시 데이터

  </Card>
</CardGrid>

:::tip
실무에서는 보통 **Source**와 **Content**를 중심으로 작업하고, 나머지 폴더는 빌드/실행 과정에서
자동 관리된다는 감각만 잡아도 충분합니다.
:::

## 솔루션 구조 (Visual Studio)

솔루션 구조는 디스크의 실제 폴더 배치를 그대로 옮긴 화면이 **아니라**, "빌드/모듈 관점"으로
재구성된 개발용 트리입니다. 프로젝트 폴더가 **파일 저장 위치** 중심이라면, 솔루션 구조는 **어떤
타깃과 모듈이 함께 컴파일되는지**를 빠르게 보기 위한 논리 구조입니다.

<Figure src="/images/ch2/5/3-solution-structure-concept-ko.svg" alt="프로젝트 폴더 구조와 솔루션 구조의 관점 차이를 보여주는 도식" caption="프로젝트 폴더=저장 위치, 솔루션=빌드 관계" />

실제 Visual Studio에서는 아래처럼 엔진/게임/도구/규칙 노드를 중심으로 트리가 정리됩니다. 중요한
점은 "물리 폴더"가 아니라 **"개발 시점의 책임 단위"** 를 본다는 것입니다.

<Figure src="/images/ch2/5/2-solution-structure.png" alt="언리얼 솔루션 구조 이미지" caption="Visual Studio 솔루션 트리" />

<CardGrid>
  <Card title="코드 파일의 의미">

  - **.h / .cpp**: 클래스 선언과 구현
  - **Build.cs**: 모듈 의존성/빌드 설정
  - **Target.cs**: 에디터/게임 타깃 빌드 설정

  </Card>
  <Card title="주요 솔루션 노드">

  - **Engine**: 언리얼 엔진 모듈과 기본 소스
  - **Games(또는 프로젝트명)**: 내가 작성하는 게임 코드
  - **Programs**: UHT 같은 도구 프로그램
  - **Rules**: Build.cs/Target.cs 등 빌드 규칙 스크립트
  - **Visualizers**: 디버깅 시 객체 시각화 설정

  </Card>
</CardGrid>

:::tip
처음에는 **Games(프로젝트명)** 와 **Rules**를 중심으로 보고, 디버깅 가독성이 필요할 때
**Visualizers**를 참고하는 흐름이면 구조를 훨씬 빠르게 익힐 수 있습니다.
:::
